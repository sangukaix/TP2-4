# TP2-4 최종 오프라인 점검 · 2026-09-20

## 범위

TP2-4의 React 라우팅·비동기 상태·저장·미리보기·관리자 표시 및 기존 AI/ML/문서 계약 검사를 수행했다. LLM 추론과 OpenAI 생성/검색은 호출하지 않았다. 기존 사용자 수정, 승인 PPT·Word 디자인, 원본 데이터, MySQL 스키마는 보존했다. 대규모 파일 이동·일괄 삭제·Git 병합/푸시는 하지 않았다.

## 수정

- 보고서별 저장 큐로 늦은 이전 저장이 최신 편집을 덮지 않게 했다. 저장 실패·재시도·페이지 종료 경고를 표시한다.
- 생성 완료와 MySQL 저장 상태를 별도 응답으로 구분한다. 브라우저 저장공간 부족을 서버 저장 성공으로 오인하지 않는다.
- 이전 미리보기 응답 무시, 실패 재시도, 전체보기 키보드 접근성, React StrictMode 중복 시작 억제.
- 기본 화면/전체보기의 챗봇 대화와 입력·요청 상태 공유. 동시에 두 패널에서 중복 전송하지 않는다.
- 보고서/템플릿 지문 기반 PDF 캐시, 동시 변환 대기 제한, 정상 PDF만 원자적으로 저장, LibreOffice 독립 프로필.
- Office 변환 후 다른 사용자 문서가 있으면 PowerPoint 전체 종료를 하지 않는다.
- 관리자 자동 새로고침은 저장 설정·실행 기록만 조회한다. 입력 중 설정을 덮지 않는다. 모델 연결은 별도 버튼이다.
- AI Router: 5개 업무 Agent, 병렬 조사·순차 작성·조건부 최종 검수, 실효 모델명, 입력/출력/파일 위치, 프롬프트·한도·명령 설명.
- 오래된 TP2-3/포트/고정 Qwen 안내 정정. 사용하지 않는 헤더 CSS와 생성 캐시의 Git 포함 정리.
- ML 학습 챗봇 키가 없으면 무거운 카탈로그 계산 전에 오류를 반환한다.

## 검사 결과

- 프론트 lint: 경고·오류 없음. Node 검사 28개 통과. production build 통과.
- AI 서버 전체 오프라인 검사 545개: 544개 통과, 1개 구형 테스트 조건 실패. 실패는 사진의 '다른 지역 참고 사진' 캡션을 미선정 사례명으로 잘못 판단한 조건이었다. 사례 설명 카드 범위로 정정했다.
- 정정 후 해당 레이아웃·미리보기·라우팅 overview·ML 챗봇 관련 18개 검사 모두 통과. 전체 545개를 불필요하게 다시 실행하지 않았다.
- 기존 문서 테스트의 오래된 페이지 번호/삭제된 슬라이드/10% 환급 기본값도 현행 승인 양식과 30% 정책(D-194)에 맞췄다. 출력 코드를 테스트에 맞춰 되돌리지 않았다.
- ML 학습 카탈로그의 단위검사는 한 지역 7개 target 확인 목적에 맞게 등록 지역 하나로 범위를 한정했다. 전국 모델을 매번 재계산하지 않는다.
- 관리자 화면 실제 브라우저 표시와 콘솔 오류 없음 확인. 미저장 모드 선택이 새로고침 후 유지되는지 확인했으며 서버 설정 저장/모델 연결 버튼은 누르지 않았다.
- 저장된 강남구 기획서가 실제 웹에서 17쪽 미리보기로 표시됨을 확인했다. 전체보기 열기/닫기 후 챗봇 입력이 동일하게 유지됨을 확인했다(질문 전송 없음).
- 기존 한 장 PPT 샘플의 정상 PDF 미리보기 반환 확인. 모의 변환의 캐시/실패/동시 요청 검사는 별도로 통과했다.
- git diff --check 통과(CRLF 안내만 있음).

## 적용과 남은 확인

1. 기존 AI 서버를 정상 종료하고 start-dev.ps1로 다시 실행해야 새 API가 실제 8212에 적용된다. 이번 UI 확인은 8213/5178 임시 확인 서버에서 수행했다.
2. 내일 개인 노트북 LLM을 켠 뒤 기획서 1건 생성 → 게시판 자동 저장 → 미리보기 → 챗봇 수정 반영 → Word/PPT 다운로드만 한 번 확인한다. 이번 검사는 실제 모델의 응답 품질·GPU 시간·최신 사례 검색 품질을 보장하지 않는다.
3. Netlify에는 최신 frontend/dist를 업로드한다. SPA redirect는 유지되지만 정적 배포만으로 MySQL/AI가 실행되지는 않는다. 로컬 API 프록시/Funnel을 사용하면 서버 노트북과 필요한 개인 노트북 연결이 켜져 있어야 한다.
4. 미리보기 서버에 PowerPoint 또는 LibreOffice가 필요하다. 변환기가 없는 환경에서는 다운로드는 유지하고 미리보기 오류를 표시한다.
5. 현재 서비스는 팀 공유 개발 구성이다. 인터넷 상시 공개 서비스로 확장할 때 일반 생성/보고서 API의 사용자 인증·접근 범위·요청량 제한은 별도 배포 작업이 필요하다. 관리자 설정 변경 토큰만으로 전체 서비스 인증을 대신하지 않는다.

원본 데이터·이관 백업·출력 예시는 삭제하지 않았다. 전체 생성과 실제 DB 저장 연동은 내일 실사용 확인 범위다.

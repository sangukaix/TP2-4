# 로컬우선(Gemma) — 2026-09-17

관리자 `/llm-control`의 `local_first_gemma` 옵션. 로컬 작업(질문 설계, 사례 비교,
본문 작성·보완, 로컬 검수, 설명·수정 챗봇)은 모두 Gemma에 연결한다.
공식 웹 조사·조사 챗봇·독립 최종 검수는 OpenAI다. 기존 생성당 유료 최대 3회와
자동 유료 대체 금지는 유지한다. 기존 `local_first`를 선택하면 이전 Qwen/Gemma 역할 분담으로 복구된다.

## 설정·점검

- 개인 `.env`와 `storage/llm_runtime_config.json`의 모드를 변경했다.
- Gemma 모델 `gemma4:26b`, 기존 문맥 131,072 유지. `OLLAMA_GEMMA_TIMEOUT_SECONDS=3600`으로
  Gemma HTTP 요청의 대기 제한만 60분으로 늘렸다. 전체 생성 제한이나 예상 완료 시간은 아니다.
- 다른 환경에서는 새 변수가 비어 있으면 기존 공통 대기 시간을 사용한다. OpenAI 시간·비용 설정은 유지한다.
- 사전 점검·지역 준비 상태·관리자 상태는 Gemma만 요구한다. Qwen이 없거나 꺼져 있어도 이 모드를 차단하지 않는다.
- 역할별 프롬프트·JSON 스키마·8,000토큰 비교 출력 한도 등 기존 계약을 재사용한다.
  도구 응답 최대 3개와 불필요한 재조회 금지를 공통 지침에 명시했다. 근거 절단·문맥 이동·무한 재시도는 허용하지 않는다.
- 실제 Gemma 짧은 JSON 1회 완료 및 `/api/ps` 문맥 131,072 확인. Qwen 추론·유료 호출 없음.
  새 모드의 전체 기획 생성 품질은 사용자가 생성한 결과로 확인한다.

최종 작업 폴더는 TP2-4다. AI 서버는 점검 당시 8212에서 실행되지 않았다. `./start-dev.ps1` 실행 후 관리자에서
`로컬우선(Gemma)` 및 실제 적용 경로를 확인한다. 환경변수 변경은 재시작이 필요하며,
관리자 모드 변경은 다음 새 요청에 적용된다. 진행 중 생성의 라우팅을 중간에 바꾸지 않는다.

## 사례 저장과 재사용의 실제 범위

완성 보고서는 근거와 함께 MySQL `strategy_reports.report_json`에 저장한다. 이 저장을
공용 웹 사례 카탈로그 자동 등록으로 취급하지 않는다. 공용 검수 카드는
`data/rag/official_case_studies.jsonl`에서 읽으며, 축제 데이터는 별도 MySQL 카탈로그를 사용한다.

조사 결과는 프로세스 메모리에 캐시한다. 기본 지역 근거 1시간, 사례 조사 6시간이며,
지역·자료·조건·라우팅·근거 파일 버전 등이 같은 요청에만 재사용한다. 실패·불충분 결과는
사례 캐시에 넣지 않는다. 서버 재시작 시 메모리 캐시는 사라진다. 저장 공식 카드가 충분하고
추가 조사가 필요하지 않으면 웹 조사를 생략한다. 지역 적용성 비교와 최종 검수는 새 기획에 수행한다.

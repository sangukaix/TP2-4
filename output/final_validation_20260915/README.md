# 제주시 마지막 생성 경로 확인

사용자 요청에 따라 전체 자동검사와 추가 품질 실험을 생략하고, 이전 수정 후 남은 제주시 실제 생성 → MySQL 저장 → PPT/Word 출력 한 경로만 확인한다.

- 지역: `50110` 제주특별자치도 제주시
- 작업 ID: `14d7385fe7004f26898f89dbd9bc840c`
- 입력: `request.json` — 자동 사업 방향, 예산 미정, 추가 자원·메모 없음
- 실제 요청 경로: Vite `5176`의 `/ai` 프록시 → AI 서버 `8112`
- MySQL80 실행 및 개인 노트북 Ollama의 Qwen/Gemma 모델 목록 확인
- 현재 생성 중인 보고서 외 기존 보고서·ML·승인 상태 변경 없음
- 운영 기본 경로 사용, 선택 기능인 구조화 비교 실험은 활성화하지 않음
- OpenAI 호출 상한 및 로컬 보완 횟수 변경 없음
- 이전 전체/관련 검사는 반복하지 않음

## 진행 기록

- 사례 조사 성공: 검색 출처가 확인된 사례 5건 채택

## 최종 결과

- 실제 생성 완료, MySQL 저장·재조회 및 PPT/Word 다운로드 성공. `generation_mode=openai`는 앱의 실제 생성 모드 이름이며 실제 모델 분담은 OpenAI 조사 + Qwen 후보/검수 + Gemma 본문이다. 오프라인 예시나 더미 전망을 사용하지 않았다.
- 선택안: **제주시 야간 문화유산 및 시설 개방 프로그램**. 서울 문화재야행 운영·예산 문서를 연결하고 강진 환급, 디지털 관광주민증 등을 비교했다. 저장 공식 사례 6건, 설계 후보 3개. 신규 검색 결과 5건의 검증과 최종 보고서의 사례 건수는 서로 다른 집계다.
- 강진 고정 출력은 아니지만, 선택한 서울 문서는 사후 효과가 검증된 성공사례가 아니라 운영·예산 참고 근거다. 내비게이션 검색량에서 야간 프로그램의 상대적 우수성을 도출하는 설명은 여전히 약하다. 지역 시설의 운영 가능 여부 등 실행 조건도 미확인이다. **81점/미승인/needs_evidence 상태를 보존했다. 기능 성공을 전체 기획 품질 승인으로 보고하지 않는다.**
- OpenAI 조사 2회(실패 1회 포함), 최종 유료 검수는 로컬 미승인으로 생략. 문맥 초과와 로컬 연결 실패 없음. 추가 생성·추가 유료 조사 없음.
- 사업기간 2026-10~12. `report.period`는 관측 현황 기간 2025-07~2026-06이고 사업기간과 구분된다.
- 방문 전망 합계 10,580,165명 → 계획 목표 10,928,766.0167명, 추가 348,601.0167명(+3.29485%). 소비 전망 합계 444,918,852,321원 → 목표 459,731,140,176.1834원, 추가 14,812,287,855.1834원(+3.32921%). 최종월 +5%는 조정 가능한 계획 가정이며 사업 효과의 ML 추정값이 아니다.
- 견적 79,057,000원 = 참여 혜택 34,870,000 + 현장 운영 21,000,000 + 시스템 8,000,000 + 홍보 5,000,000 + 평가 3,000,000 + 예비비 7,187,000. 참여량 3,487건 = 추가 방문 목표 × 1% 올림. 단가와 참여량 비중은 계획 가정이다.
- 저장 보고서 전체가 생성 응답과 동일. PPT 내장 차트의 네 계열과 Word 월별 표를 저장 전망·목표 값과 대조해 모두 일치. 임시 견적 항목 합계 일치.
- PPT 16장, Word 16쪽을 읽기 전용 PowerPoint/Word로 렌더해 모든 페이지 시각 확인. 표·그래프·사진 설명 및 출처가 읽히며 잘림 없음. 번들 분석 런타임에는 앱 의존성 httpx가 없어 앱 산식만 프로젝트 Python으로 계산하고, OOXML 대조는 번들 런타임으로 분리했다. 신규 설치 없음.

## 출력 일정 수정

- 실제 본문은 준비 10월 → 운영 11~12월 → 평가 12월인데 기존 4단계 안내는 첫 3개 단계를 그대로 할당해 운영에 준비 단계의 10월을 표시했다.
- 공통 `execution_groups`에서 추가 준비 단계들을 앞쪽으로 합쳐 마지막 운영 준비·운영·평가의 일정을 유지한다. Word/PPT 공통 적용, 캐시 버전 Word v11/PPT v22. 저장 보고서는 수정하지 않는다.
- 이 재현 사례의 PPT/Word 일정 일치·원본 불변을 검증하는 unittest **1개**만 추가 실행해 통과. `execution_period_test.log`. 전체 검사·frontend 검사·ML 학습은 반복하지 않았다.
- 진행 중인 다른 작업이 없음을 SQL에서 확인 후 이번 검증에서 시작한 AI 서버만 재시작. 동일 보고서를 다시 내려받았고, 재시작 후 LLM trace 호출 수 0을 확인했다.
- 수정 전 파일은 `제주시_일정수정전.*`, 최종 전달 파일은 `제주시_최종검증.*`. 원래 저장 보고서와 품질 상태 그대로 유지.
- 수정 후 PPT 7·14장, Word 7쪽을 재확인. PPT 14장은 모델 표시 순서만 달라졌으며 값은 같다. 다른 페이지는 이전 렌더와 SHA256이 동일하다. 숫자 대조도 다시 일치했다.

# 두 지역 최종 생성 검증

사용자 승인 범위: 기존 생성 경로에서 부평구(28237), 제주시(50110)의 생성 → 저장 → PPT/Word 다운로드를 확인한다. 새로운 후보 실험 계약은 활성화하지 않는다. 기존 모델·유료 상한·원자료·저장 보고서는 보존한다.

완료 기준:
- 두 지역 모두 실제 생성 결과이며 오프라인 샘플로 대체되지 않는다.
- 생성 당시 지역 관측·ML 기간과 수치가 원래 자료와 일치한다.
- 비교 사례의 출처와 운영 방식이 실제 응답에 연결되며, 가정 목표를 관측 성과나 ML 사업 효과로 표현하지 않는다.
- 새 보고서가 MySQL에 저장되고 PPT/Word 다운로드 및 재조회가 가능하다.
- 두 문서의 사업·기간·방문/소비 전망·목표·견적이 동일하고 실제 렌더에서 읽을 수 있다.

이번 점검에서 새 기능·파인튜닝·무제한 재생성은 추가하지 않는다. 실패하면 해당 원인과 영향 범위를 기록하며, 검사 통과나 오류 건수 감소만으로 품질을 승인하지 않는다.

## 실행 기록

- 부평구 웹 생성 job: `e94c3bbe997245d788785b99c98e079a`
- 두 지역 입력 점검: `readiness.json` (모두 ML/SQL 사용 가능, 비교지역 각 5곳)
- 관련 unittest 141개 및 프런트엔드 19개, lint/build 통과.
- 부평구 지역 웹 조사에서 `OPENAI_UNVERIFIED_WEB_SOURCE` 발생. 해당 조사 응답은 제외됨.
- 부평구 사례 조사: 검색 기록 확인된 3건 채택, URL 필드에 두 주소를 합쳐 반환한 1건 제외. 실제 사례 내용을 확인하기 전 품질 승인하지 않음.
- 두 지역 실제 실행 결과: 부평 생성·저장·다운로드 완료, 제주시 후보 연결 단계 중단. 두 지역 모두 통과한 결과가 아니다.

## 회귀 검사 중 발견한 격리 문제

AI unittest 전체 453개는 통과했지만, 3개 테스트 모듈의 `TestClient(main.app)`가 실제 startup을 실행하여 MySQL의 진행 작업을 재예약했다. 테스트 프로세스는 로컬 모델 사전 연결에서 실패했고 이번 부평 검증 job의 DB 상태를 failed로 바꿨다. 실제 서비스 프로세스는 계속 running이었다. 변경된 job은 이번 검증 job 1건만 확인됐고, 해당 행의 실패 상태와 오류가 일치할 때만 현재 서비스의 running 상태로 복구했다. 기록: `test_isolation_incident.json`.

부평 작업 종료 후 테스트 소스를 수정했다. 학습 API/입력 검증용 TestClient에서 저장소 초기화와 중단 작업 복구를 격리했다. 관련 19개 검사를 실제 저장소 `_connect` 호출 시 실패하도록 감싸 실행했고 DB 접속 없이 통과했다. 검사가 통과했다는 사실만으로 부작용이 없었다고 판단하지 않는다.

## 부평 실제 결과

- 기존 운영 경로에서 신규 보고서 생성, 웹 저장, 재조회, PPT/Word 다운로드 완료. 새로고침 후에도 같은 job을 조회했고 중복 생성을 하지 않았다.
- 선택 사업: **부평역 권역 야간 체류 유도 프로그램**. 새로 조사한 인천 송도·개항장·월미도 야간관광 사업이 핵심 운영 근거이며, 강진 환급과 디지털 관광주민증을 대안으로 비교했다. 강진만 고정 출력하는 경로는 아니다.
- OpenAI 2회(지역 조사 1회 실패 포함). Qwen 후보/보완 및 검수, Gemma 본문/보완이 실행됐다. 최종 유료 검수는 로컬 미승인으로 실행되지 않았다. 문맥 초과·로컬 연결 실패 없이 실제 생성 프로세스가 끝났다.
- 원래 검수 기록은 81점/미승인이다. 담당자 표현의 오탐 2건이 있었지만 후보 비교 설명의 약점도 남았다. 점수나 승인값을 바꾸지 않았다.
- 실제 출력 PPT 16장, Word 16쪽을 네이티브 PowerPoint/Word로 렌더하고 전부 시각 확인했다. 그래프·표 표시와 글자 잘림을 확인했으며, PPT 차트의 내장 수치 및 Word 표 수치가 저장 보고서와 일치한다.
- 3개월 전망: 방문 11,268,139명, 소비 243,545,949,020원. 목표: 방문 11,643,131.483명, 소비 251,746,865,980.10원(문서에서는 반올림). 최종월 목표 +5%는 계획 가정이다.
- 견적 83,600,000원 = 참여 혜택 37,500,000 + 운영 22,500,000 + 시스템 8,000,000 + 홍보 5,000,000 + 평가 3,000,000 + 예비비 7,600,000. 참여량 3,750건은 추가 방문 목표 × 1%를 올림한 운영량 가정이다.
- 새 인천 사례의 `published_at` 메타데이터는 2024-05-29로 반환됐으나 공식 페이지의 자료 제공일은 2024-06-11이다. 공식 사업 내용은 확인했지만 이 날짜 오류를 포함한 원래 응답을 보존한다. 원문: https://www.incheon.go.kr/IC010205/view?repSeq=DOM_0000000010085993
- 저장 결과/숫자 검증: `bupyeong_report.json`, `bupyeong_saved_report.json`, `bupyeong_document_audit.json`.

## 실제 응답에서 확인한 공통 코드 수정

- “안전 관리자가”, “기획팀이”가 명시된 실행 단계의 담당 누락 오탐을 수정했다. 담당자를 확보할 예정이라는 문구는 여전히 실제 담당 명시로 취급하지 않는다.
- 근거·가정 표시 없는 숫자 중단 조건을 단순히 ‘기획 가정’으로 접두해 유지하지 않는다. 기준선·표본수·판단 방향을 착수 전 확정하는 문장으로 보정하고 원문을 감사 기록에 보존한다. 같은 후보에 연결된 동일 문장만 동기화한다. 명시적으로 가정 표시된 사용자 목표를 일괄 제거하지 않는다.
- 관련 검사 80개 통과. 기존 보고서 및 승인 상태는 변경하지 않았다.

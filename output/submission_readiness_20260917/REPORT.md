## 미통과 검사의 해석

23개 미통과를 모두 새로운 런타임 결함으로 보거나 모두 무해한 옛 검사로 보아서는 안 된다.

- 구 포트 5176을 기대하는 검사 1개는 TP2-4의 현재 5177 설정과 명백히 다르다.
- 구 PPT v20/14장/이전 shape 이름·고정 슬라이드 위치·제목을 기대하는 검사가 현재 v46 출력과 충돌한다. 최신 승인 디자인에 맞춰 검사를 갱신하고, 수치·출처·사용자 목표 보존 검사는 유지해야 한다.
- 예산 검사 2개는 예산 3,000만 원을 전액 소진해야 한다거나 사용자 목표율 증가에 견적이 반드시 증가해야 한다는 기대다. 현재 운영량·참여 목표 기반 견적과 계약이 다르며, 별도 운영 목표 검사의 합계·상한·수동 목표 보존은 통과했다. 기존 실패를 지우거나 모델/산식을 예전 것으로 되돌리지는 않았다.
- 앞선 D-189 문서의 통과 개수 및 '모두 PPT 양식 불일치' 설명은 이번 실행 결과를 대신할 수 없다. 현재 결과는 위 숫자와 로그를 따른다.

## 지역 사례 문제의 해결 범위

긴 source/case JSON의 페이지 분할·전 페이지 읽기·무손실 복원·미조회 인용 차단 검사는 통과했다. 축제 수치/기간 보존, 다른 지역 자료 혼동 방지, 공식 허용 도메인, 조사 실패 처리 관련 회귀 검증도 포함됐다.

다만 기존 `docs/DAEJEON_LINKED_SCENARIO_20260916.md`는 14B 모델 실제 후보 비교에서 긴 원문 오류가 재발하지 않았지만 선정 설명의 지역 구체성·수치 활용·산식 설명은 미달이라고 기록한다. 현재 27B 모델로 이를 해소했는지는 신규 전체 생성으로 검증하지 않았다. 따라서 '사례 문제 전부 해결'로 승인하지 않는다.

## 제출 전 남은 항목

1. 실패 테스트를 최신 승인 계약에 맞춰 정비하고 실제 기능 결함과 구분한다. 검사를 무조건 약화해 통과시키지 않는다.
2. 대표 지역을 새로 생성해 조사 → 사례 비교 → Gemma 본문 → 로컬/독립 최종 검수 → 저장 → Word/PPT 출력까지 확인한다. 이전 문제를 재현하기 쉬운 대전 서구가 한 후보이나, 사용자가 지역·조건과 유료 호출을 승인한 뒤 진행한다.
3. 사례를 선택한 이유에 해당 지역의 실제 수치·장소·운영 차이가 있는지, 목표/견적/계획 가정이 사실처럼 쓰이지 않았는지 사람이 확인한다. 문서의 페이지 넘침·사진 출처·표/차트·다운로드도 확인한다.
4. 원자료 카탈로그 250개가 `needs_exact_download_url`로 남아 있다. 이미 확보된 기관·파일명·해시·기간은 보존하고, 확인 가능한 다운로드 조건·증빙을 보완한다. URL을 임의로 만들거나 verified로 일괄 변경하지 않는다.
5. 250지역×7지표=1,750개 평가 항목 중 533개는 `below_baseline_on_test`이며 1,028개는 `seasonal_baseline`이다. 나머지는 mixed 111, limited 74, no_test_improvement 4다. 모델 로딩 성공을 예측 정확도 우수로 홍보하지 않고 지역/지표별 평가를 제시한다. 이번 점검에서 재학습하지 않았다.
6. 실제 공모전 공고/제출 양식·심사 기준, 사용자 평가 증빙, 외부 배포 요구사항은 별도 대조가 필요하다. 현재 LAN 개발 서버 실행과 운영 배포 완료를 혼동하지 않는다.

현재는 **개발 결과를 설명하고 중간 시연할 근거는 확보했지만, 최종 제출 완료 판정은 보류**한다. 초록색은 입력자료 준비, 개별 기획서의 최종 검수·출력 검증은 별도다.
